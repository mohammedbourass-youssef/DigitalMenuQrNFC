# API Endpoints & Permissions

Generated by the `EndpointReport` tool (backend/NFC_Backend/EndpointReport). It scans every
controller action via reflection and flags endpoints that have neither `[AllowAnonymous]` nor
`[HasPermission]`.

Run it with:

```powershell
dotnet run --project backend/NFC_Backend/EndpointReport
# add -p:UseAppHost=false if the API is currently running and locks the exe
```

Legend — permission actions map to the `role_permissions` columns: `READ` = CanRead,
`WRITE` = CanAdd, `UPDATE` = CanEdit, `DELETE` = CanDelete.

## Flagged (neither [AllowAnonymous] nor [HasPermission])

- `OrdersController.Pay` [POST /api/Orders/Pay] — creates an Invoice (ComingSoon, pro-plan-only) + pays an order; annotating with `Invoices:WRITE` would 403 free-plan owners. Options: `Invoices:WRITE + Orders:UPDATE`, or `Orders:UPDATE` only.
- `OrdersController.GetPaymentReceipt` [GET /api/Orders/{orderId:guid}/Payment] — reads a receipt; same free-plan concern with `Invoices:READ`.

## Open decisions

1. `GET /api/features` — the feature catalog itself has no feature code (option: `Roles:READ`, or keep any-authenticated).
2. `GET /api/PaymentMethods/Enabled` — requires `PaymentMethods:READ`, pro-plan-only; confirm free plans don't use the cashier screen.
3. Restaurants → `Settings` and Plans → `Subscription` were closest-match picks — confirm.
4. Order status CRUD mapped to `Orders` (WRITE/UPDATE/DELETE/READ) — confirm these aren't a separate feature.
5. **Blocking**: owners have no `user_roles` rows and `PermissionRepo.GetPermissionsAsync` loads permissions only via `user_roles → role_permissions`, so every `[HasPermission]` endpoint returns 403 until TenantOwner/SuperAdmin is granted implicit permissions or owners are assigned the seeded TenantAdmin role.

## Security findings

1. `/api/admin/payment-statuses` mutates a global, non-tenant-scoped table — any tenant owner can affect all restaurants; should be platform/SuperAdmin-only or tenant-scoped.
2. `GET /api/Orders/Statuses` previously had no `[Authorize]`; now gated by `Orders:READ` via the middleware (consider adding `[Authorize]` explicitly).
3. Tenant isolation verified elsewhere: Categories, MenuItems, Tables, Orders, PaymentMethods, Invoices, Restaurants all filter by the token's TenantId; `/api/tenant/*` is subdomain + session-scoped.

## Middleware pipeline order (fixed)

`UseRouting → UseCors → UseRateLimiter → UseAuthentication → Tenant/Session (scoped) → Language → Currency → PermissionMiddleware → UseAuthorization → MapControllers`
