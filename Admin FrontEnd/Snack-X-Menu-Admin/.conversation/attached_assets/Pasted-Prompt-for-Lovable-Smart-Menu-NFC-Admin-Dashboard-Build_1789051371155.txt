Prompt for Lovable — Smart Menu NFC (Admin Dashboard)

Build a simple, minimal admin dashboard web app for restaurant owners to manage their digital menu system. This is a proof-of-concept / demo UI — the goal is clean and pleasant, not feature-rich. Keep every screen simple and functional, but still visually beautiful (good spacing, good typography, nice color use) — not a bare bones ugly admin panel.

Core concept

This is the admin/back-office side of a restaurant NFC menu system (the customer-facing menu is a separate app).

Use demo/mock data only for now — no real backend integration. Hardcode sample data directly in the frontend so it works standalone. A real API will be connected later.

Desktop-first is fine here (unlike the customer menu, which was mobile-first) since restaurant owners will mostly use this on a laptop/tablet, but it should still be usable on a tablet screen.

1. Login page

Simple login screen: email + password fields, a "Login" button.

Just a visual/mock login — no real auth logic needed, can redirect straight to the dashboard on submit with any input.

Clean, centered card layout, restaurant/food-themed but minimal (no need for heavy imagery).

2. Dashboard (small overview)

A simple landing page after login with a handful of key stats as cards, e.g.:

Orders today

Revenue today (mock number)

Active tables / occupied tables

Pending orders count

Keep it to 3-5 stat cards max — this should feel like a quick glance, not a full analytics suite.

A simple sidebar or top navbar for navigation between sections (Dashboard, Orders, Menus, Tables, Settings).

3. Orders page (the most important screen)

List of incoming/active orders, each showing:

Table number

Order items (name, quantity, price)

Order total

Status (e.g. "New", "Preparing", "Ready", "Completed") shown as a colored badge

Timestamp (how long ago it came in)

Ability to mark an order as complete (a clear action button per order, e.g. "Complete Order").

Ability to edit an order while it's active:

Add an existing menu item to the order

Increase/decrease quantity of items already in the order

Remove an item from the order

New orders should visually stand out (e.g. a highlighted border or "New" badge) so staff notice them at a glance.

A simple filter or tabs to separate: New / In Progress / Completed orders.

4. Menus page (menu management)

A place to create and manage the menu: categories and products.

For categories: name, and ability to add/edit/delete a category.

For products, a simple form/modal to create or edit an item with:

Name

Image (upload or URL placeholder)

Short description

Price

Category (dropdown)

Promotion toggle (if on, show a discounted price field)

Display products in a simple table or card grid, grouped by category, with edit/delete actions per item.

5. Tables page (table management)

A place to create and manage restaurant tables.

Simple list/grid of tables showing table number/label and status (e.g. Free / Occupied).

Ability to add a new table (auto-suggest next number, or manual label input) and delete a table.

Each table entry conceptually represents one NFC tag — keep this simple, just name/label + status is enough for the demo (no need to simulate NFC itself).

6. Settings page (branding / UI customization)

A place to customize the restaurant's branding, which will control how the customer-facing menu looks:

Restaurant name (text input)

Logo upload (or image URL placeholder)

Primary color picker (this should control the accent color used across the customer menu app)

Show a small live preview of how the branding looks (e.g. a mock mini header/card previewing the logo, name, and color together) so the effect of changes is visible immediately.

Keep this page short — just these 3 branding fields is enough for the demo, no need for extra settings yet.

Design direction

Minimal and simple layout — sidebar (or top nav) + content area, nothing more elaborate.

Clean, modern, a little bit of personality (rounded cards, soft shadows, decent whitespace) — beautiful through simplicity, not through complexity.

Use a neutral base palette (white/light gray backgrounds, dark text) with the brand accent color used for buttons, active states, and highlights.

Status badges (order status, table status) should use clear, distinct colors (e.g. green = ready/free, orange = in progress, gray = completed, red/highlight = new).

Good, readable typography — this is a data/functional tool, clarity matters more than flair here.

Trilingual UI is not required for this admin panel — English only is fine for this demo.

Demo data to include

1 demo restaurant profile (name, logo placeholder, accent color) matching the "Snack X" theme from the customer menu demo

4-5 sample tables with mixed Free/Occupied status

4-5 categories with 3-5 products each (reuse similar demo data style to the customer menu — burgers, drinks, desserts, etc., with a couple marked as promotions)

4-6 sample orders in different statuses (New, In Progress, Completed) tied to different tables, with realistic item lists and totals

Not needed right now

No real authentication or backend/API calls — everything can be local/mock state

No user roles/permissions (single admin user is fine)

No payment or invoicing features

No analytics/reporting beyond the small dashboard stat cards

No multi-language support in the admin UI itself
